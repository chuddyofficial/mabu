# MABU Dashboard

A personal OSINT research platform for organizing and documenting publicly available digital footprint data — multi-entry case files, cross-case correlation, real WHOIS/DNS/handle lookups, and PDF reporting, behind single-admin authentication. Runs locally on your own machine or on a private VPS you control.

> **Scope note:** MABU is a note-taking, organization, and correlation tool for information you already have lawful, legitimate access to (public directories, platforms' own lookup/validation tools, server logs you own, protocol-level lookups like WHOIS/DNS, etc.). It does not scrape, brute-force, or query third-party aggregators/breach databases. Always follow the terms of service of any platform you research and applicable law in your jurisdiction.

## Features

The dashboard uses a full CRT-terminal / matrix aesthetic — animated boot sequence, scanline overlay, glowing green-on-black monospace UI — on top of the following modules:

- **Auth** — multi-user accounts with **admin**/**investigator** roles, bcrypt-hashed passwords, server-side session cookies, per-IP login rate limiting (5 attempts / 5 min), CSRF-protected state-changing requests, and a full audit log
- **Research / Vault** — cases hold multiple timestamped entries, a status (`open` / `closed` / `cold`), tags (with filtering), file attachments per entry, and a full activity log
- **Case templates** — pre-filled tag/summary/findings skeletons for common investigation types (phishing, impersonation, harassment, fraud) — pick one when creating a case
- **Related-case detection** — as you type identifiers into a new case, MABU checks the vault live and warns if that email/username/IP/name already appears in an existing case
- **Correlate** — scans every decryptable case in the vault, auto-detects shared emails/usernames/IPs/phones/names, and clusters likely-same-person cases together
- **Reporting** — generates a polished PDF report per case, or per correlation cluster (multi-case), with entries, identifiers, and activity log
- **Public Records** — real WHOIS and DNS lookups, live handle-existence checks (HTTP requests to a platform's own profile URL), local phone number parsing (carrier/region/timezone via libphonenumber, no external API), and an opt-in HaveIBeenPwned breach check using your own API key
- **Image metadata** — extracts EXIF data (camera info, timestamps, embedded GPS coordinates) from an uploaded image, entirely locally
- **Admin panel** (admin role only) — create/deactivate/reactivate users, reset passwords, change roles, and browse the full audit log
- **Reader** — decrypt and view raw `.mabu` case data, export to JSON
- **Timeline** — chronological view of all decryptable cases, plus an SVG relationship graph
- **Email / Username / Discord / Network-IP / Hash & Encode** — the original manual-tracking and utility tools (format validation, snowflake decoding, CIDR calculator, hashing, etc.)

## First-time Setup

```bash
python setup.py
```

`setup.py` is a full installer, not just a key generator. It will:
1. Detect your environment and check for Python dependencies, offering to `pip install` any that are missing
2. Create the vault directory
3. Generate the vault encryption key (`vault/.mabu-default-key`)
4. Generate the session signing secret (`config/session-secret.key`)
5. Prompt you to create the first **admin account** — a username and a password (min 8 characters), stored as a bcrypt hash in `config/users.json` (never plaintext). Additional users (admin or investigator role) are managed afterward from the dashboard's **Admin** panel, not through `setup.py`.
6. Optionally configure a **public domain** — generates ready-to-use `deploy/nginx.conf` and `deploy/mabu.service` files and prints the exact commands to install them (see the VPS deployment section below)
7. Print a status summary of everything that's configured

Useful flags:
```bash
python setup.py --reset-admin                        # replace the admin account
python setup.py --reset-vault-key                     # regenerate the vault key (invalidates old default-key-encrypted files)
python setup.py --domain mabu.example.com              # (re)configure the public domain + regenerate deploy/ files
python setup.py --skip-deps                            # skip the dependency check/install step
python setup.py --non-interactive --username admin --password-env MABU_ADMIN_PW --domain mabu.example.com   # fully scripted install
```

Re-running `setup.py` is always safe — nothing destructive happens unless you explicitly pass a `--reset-*` flag.

### Start the server

```bash
cd api
python mabu-server.py
```

The server listens on `http://127.0.0.1:5057`. Open `index.html` in a browser — the login screen appears first; log in with the admin account you created.

### Migrating older vault data

If you have `.mabu` files from before v3 (single-note format), run the migration once:

```bash
python migrate_vault.py --dry-run   # preview
python migrate_vault.py             # migrates all default-key files, backing them up first
```

Files are backed up to `vault/mabu-files-backup-<timestamp>/` before anything on disk is rewritten. Passphrase-protected files must be migrated individually: `python migrate_vault.py -f case.mabu -p yourpassphrase`.

## The `.mabu` File Format (v2)

Binary container (unchanged since v1):

```
[4 bytes]  magic "MABU"
[1 byte]   format version (2)
[8 bytes]  encrypted payload length
[N bytes]  Fernet-encrypted JSON payload
[32 bytes] SHA-256 checksum of the encrypted payload
```

The JSON payload is now a **case**, not a single note:

```json
{
  "schema": 2,
  "case_id": "uuid4 hex",
  "title": "Case-0142",
  "status": "open",
  "investigator": "analyst_handle",
  "created": "2026-09-13T10:00:00+00:00",
  "updated": "2026-09-13T11:30:00+00:00",
  "tags": ["..."],
  "entries": [
    {
      "entry_id": "uuid4 hex",
      "date": "...", "author": "...", "summary": "...", "findings": "...",
      "emails": ["..."], "phones": ["..."], "usernames": ["..."],
      "names": ["..."], "ips": ["..."], "sources": ["..."]
    }
  ],
  "activity_log": [
    {"date": "...", "action": "created", "detail": "..."}
  ]
}
```

Encryption is **Fernet** (from `cryptography`). Files saved without a custom passphrase use the vault's default key; files saved with a passphrase derive their key from `SHA-256(passphrase)`. Legacy v1 files (flat single-note schema) are still readable everywhere and auto-upgraded in memory on decrypt — `migrate_vault.py` makes that upgrade permanent on disk.

## mabu-reader.py / mabu-open.py

Two standalone tools for working with `.mabu` files outside the dashboard — a CLI (`mabu-reader.py`) and a GUI app (`mabu-open.py`, launch via `MABU Reader.vbs` for zero console window). Both are unaffected by the v3 auth/case changes and read the same `.mabu` format directly. See inline `--help` / the app's own UI for usage.

## Deploying to a Ubuntu VPS

This assumes a fresh Ubuntu 22.04/24.04 server and a domain (or subdomain) pointed at its IP already.

### 1. Server prep

```bash
sudo apt update && sudo apt install -y python3 python3-venv python3-pip nginx git
```

### 2. Clone and run the installer with your domain

```bash
git clone https://github.com/<your-username>/<your-repo>.git mabu
cd mabu
python3 -m venv venv
source venv/bin/activate
pip install -r api/requirements.txt
python setup.py --domain mabu.yourdomain.com
```

Run this interactively over SSH (not in a script) so the admin password never touches shell history or a file. `setup.py` will:
- generate the vault key and session secret
- prompt you to create the admin account (bcrypt-hashed, never plaintext)
- write `config/domain.txt` and generate `deploy/nginx.conf` + `deploy/mabu.service`, pre-filled with this server's actual paths and your domain
- print the exact copy/paste commands for the remaining steps (repeated below)

You can also configure the domain non-interactively later (or reconfigure it) with `python setup.py --domain mabu.yourdomain.com` — it's idempotent and won't touch an existing admin account or vault key.

### 3. Install the generated systemd service

```bash
sudo cp deploy/mabu.service /etc/systemd/system/mabu.service
sudo systemctl daemon-reload
sudo systemctl enable --now mabu
sudo systemctl status mabu
```

Run the app as a **dedicated non-root user**, not root — pass `--service-user yourusername` to `setup.py` if it isn't `mabu`, so the generated service file matches.

### 4. Install the generated nginx config, then get HTTPS

```bash
sudo cp deploy/nginx.conf /etc/nginx/sites-available/mabu
sudo ln -sf /etc/nginx/sites-available/mabu /etc/nginx/sites-enabled/mabu
sudo nginx -t && sudo systemctl reload nginx

sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d mabu.yourdomain.com
```

certbot rewrites the nginx config to redirect HTTP → HTTPS automatically. Since the generated `mabu.service` already sets `MABU_PUBLIC_ORIGIN=https://mabu.yourdomain.com` in its environment, `mabu-server.py` automatically turns on `SESSION_COOKIE_SECURE` and restricts CORS to that exact origin — no manual code edits needed. The frontend (`js/mabu-core.js`) also auto-detects it's being served over http/https and calls the API same-origin through nginx's `/api/` proxy, rather than hardcoding `127.0.0.1`.

### 5. Updating via git pull

Since the repo is public, updates are a simple pull + restart:

```bash
cd /home/mabu/mabu
git pull
source venv/bin/activate
pip install -r api/requirements.txt   # only if dependencies changed
sudo systemctl restart mabu
```

**Never commit** `config/admin.json`, `config/session-secret.key`, `config/domain.txt`, `deploy/`, `vault/.mabu-default-key`, or any `.mabu` file — `.gitignore` already excludes all of these, but double-check `git status` before any `git add -A` on the VPS too.

### 6. Firewall

Only expose 80/443 (and SSH) — the Flask app itself should never be reachable directly from the internet:

```bash
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw enable
```

## Multi-user & Roles

MABU supports multiple accounts with two roles:
- **admin** — full case access, plus the Admin panel (create/deactivate users, reset passwords, change roles, view the audit log)
- **investigator** — full case CRUD (create/view/edit cases, run lookups, generate reports), no user management

`setup.py` only ever creates the first account (as admin). To add more users, log in as an admin and use the **Admin** tab in the sidebar. Deployments created before multi-user support (a single `config/admin.json`) are transparently migrated into the new `config/users.json` store the first time the server starts — the old file is renamed to `admin.json.migrated` rather than deleted.

## Opt-in Breach Checking (HaveIBeenPwned)

The **Public Records → breach --check** tool uses the official HaveIBeenPwned API, which requires your own paid API key (HIBP charges for API access as an anti-abuse measure — MABU does not proxy or share a key). To enable it:

```bash
export MABU_HIBP_API_KEY="your-key-here"   # add to your shell profile or systemd service Environment= line
```

Without a key set, the tool clearly reports itself as "not configured" rather than failing silently or guessing.

## Security Notes

- Every API route except `/api/health`, `/api/auth/status`, and `/api/auth/login` requires an authenticated session (`@login_required`); user-management and audit-log routes additionally require the `admin` role (`@admin_required`).
- Passwords are hashed with **bcrypt**, never stored or logged in plaintext. There is no "forgot password" flow by design — a locked-out user's password can only be reset by an admin (via the Admin panel) or, for the very first account, by re-running `setup.py --reset-admin` with filesystem access to the server.
- **Login attempts are rate-limited** to 5 failures per (username, IP) pair within a 5-minute window, to slow brute-force attempts. This resets on server restart (in-memory only).
- **All state-changing requests (POST/PUT/PATCH/DELETE) require a CSRF token** (`X-CSRF-Token` header, issued per-session on login) in addition to the session cookie — this stops a malicious page from silently triggering actions using your logged-in session.
- **Every security-relevant action is audit-logged**: logins (success/failure/rate-limited), logouts, password changes, user creation/deactivation/deletion/role changes, case creation, entries, and status changes — visible to admins in the Admin panel.
- `config/users.json` (password hashes) and `config/session-secret.key` (cookie signing key) must never be committed or exposed — treat them like any other credential file.
- The vault default key (`vault/.mabu-default-key`) is equally sensitive — anyone with that file and your `.mabu` files (not passphrase-protected) can decrypt them.
- For anything especially sensitive, use a per-case passphrase instead of relying on the default key.
- WHOIS/DNS/handle-check lookups only talk to the target's own public infrastructure (its WHOIS server, DNS resolvers, or profile page); the breach-check tool only talks to the official HIBP API with a key you provide — nothing here scrapes third-party aggregators or unofficial breach dumps.
- Attachments are stored base64-encoded **inside** the encrypted `.mabu` file itself (capped at 8MB per file, 10 per entry) — they inherit the case's encryption, so there's no separate unencrypted file on disk to worry about.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Login screen says "no admin account exists yet" | Run `python setup.py` on the server |
| Sidebar shows "API Offline" | Make sure `mabu-server.py` is running (or `systemctl status mabu` on the VPS) |
| 401 errors in browser console | Session expired or not logged in — refresh and log in again |
| "Decryption failed" in Reader | Wrong passphrase, or the file needs the default key instead |
| Vault list is empty | No `.mabu` files exist yet — create one via the Research tab |
| Correlate shows 0 nodes | All vault files are passphrase-protected (correlation only scans default-key-decryptable cases) |
| CORS/cookie issues from `file://` | Flask-CORS + `supports_credentials=True` correctly handles the `null` origin browsers send for local files — confirm you're not blocking cookies in browser privacy settings |
| 403 "Invalid or missing CSRF token" | The session's CSRF token wasn't sent — refresh the page to re-fetch it from `/api/auth/status`/login, don't reuse a token across sessions |
| 429 "Too many failed attempts" on login | Rate limit hit (5 failures / 5 min for that username+IP) — wait, or restart `mabu-server.py` to clear the in-memory limiter |
| "Admin panel" tab doesn't appear | You're logged in as an `investigator`, not `admin` — that tab and its routes are admin-only by design |
| Breach check always says "not configured" | Set the `MABU_HIBP_API_KEY` environment variable on the server (see the HaveIBeenPwned section above) and restart `mabu-server.py` |
